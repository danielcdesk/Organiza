# Organiza — direção e auditoria para a atualização global

Fonte: especificação de 54 seções fornecida pelo usuário em 18/10/2026, no anexo `Pasted text.txt`. Este documento registra as decisões de implementação; a especificação original continua sendo a referência para os detalhes de aceite.

## Intenção do produto

Pessoa: alguém conferindo dinheiro, compromissos e próximos passos no celular ou no PC, geralmente com pouco tempo. Tarefa principal: entender o mês corrente e registrar a próxima ação sem confundir dinheiro previsto com realizado. Sensação: clareza de um extrato bem organizado, com densidade útil e controles confortáveis.

Domínio: competência mensal, saldo, fatura, vencimento, renda, distribuição, orçamento, meta e histórico. Mundo de cores: papel de extrato, grafite de números, verde de entrada, âmbar de atenção, vermelho de vencido e laranja da identidade atual do Organiza. Assinatura visual: um resumo do mês que liga cada valor a uma ação concreta; histórico fica em Relatórios. Evitar grade de cartões iguais, navegação mensal na Visão Geral e formulários gigantes.

Antes de cada alteração visual: o valor ou ação mais relevante lidera; cores semânticas têm função financeira; superfícies usam a extensão `OrganizaDesignTokens`; tipografia diferencia valor, rótulo e metadado por peso e contraste; espaçamento segue a base de 4/8 px; alvos de toque continuam com no mínimo 44 px no mobile.

## Regras de dados

- Um único valor-base de renda planejada: `profileIncomeInCents` quando definido; série salarial é previsão de caixa, e transação salarial é realizado. Não somar as três fontes para o mesmo salário.
- A distribuição vigente se aplica a partir do mês em que é salva. Meses anteriores só mostram versão histórica quando existe dado verificável; migração não inventa distribuições antigas.
- Pagamento de fatura movimenta a conta uma vez e não entra novamente nas despesas categorizadas pelas compras. Data é civil, não instante.
- Arquivos de imagem de metas são copiados à pasta privada pelo serviço existente; ausência de imagem sempre usa fallback local.
- Desktop e Mobile reutilizam modelos, regras e widgets responsivos; diferenças são de apresentação, não de fonte de dados.
- Código é publicado na branch do GitHub após testes; não criar release público nem instaladores oficiais sem pedido específico.
