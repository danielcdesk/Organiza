# Global UX and Financial Flows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar a atualização global de experiência e fluxos do Organiza com a mesma regra financeira no Windows e Android, preservando dados e publicando o código testado no GitHub.

**Architecture:** Conservar `OrganizaStore` como fachada, `AppDatabase` como persistência local e widgets responsivos compartilhados. Introduzir serviços/formatadores de domínio onde houver regra reutilizada; migrações atômicas e idempotentes para novos dados; cada etapa termina com testes, documentação e commit próprio.

**Tech Stack:** Flutter/Dart, SQLite local, Material, testes unitários e de widget, Git/GitHub.

**Spec:** `docs/superpowers/specs/2026-10-18-global-ux.md` e anexo original `Pasted text.txt` fornecido pelo usuário.

## Global Constraints

- Desktop e Mobile têm as mesmas regras financeiras; diferenças de layout são permitidas.
- Sem rede, login remoto, telemetria ou dependência de serviço externo.
- Dinheiro em centavos inteiros; datas de negócio sem fuso; `created_at` continua UTC.
- Não solicitar nem armazenar número completo de cartão ou CVV/CVC.
- Escritas de várias linhas em `AppDatabase.transaction`; migrações preservam dados e são testadas desde schema 1.
- Imagens pessoais vão para a pasta privada dentro do limite de `LocalImageService`.
- Preservar tema escuro, alvos de toque mobile e funcionalidades existentes.
- Publicar commits na branch existente; não publicar release oficial ou instaladores sem solicitação nova.

## Review Focus

1. Colar `R$ 1.234,56` sobre seleção parcial não pode deslocar centavos: teste do formatador no Task 1.
2. Salário de perfil e série salarial simultâneos não podem dobrar o orçamento: teste do store no Task 3.
3. Tentar pagar a mesma fatura duas vezes não pode debitar duas vezes: teste do store no Task 7.
4. Cor personalizada clara/escura precisa manter texto legível: teste de contraste no Task 7.
5. Meta com imagem removida ou inexistente precisa renderizar fallback sem erro: teste de widget no Task 8.
